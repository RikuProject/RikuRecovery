# Riku Recovery

Ядро собственного рекавери для Linux/Android-устройств (в первую очередь
для детских часов на Unisoc, например Aimoto Pro Indigo 4G). Написано на C,
без зависимостей, кроме libc.

## Что уже есть

| Модуль | Файл | Что делает |
|---|---|---|
| Запуск | `main.c` | Работает как PID 1 (`/init`) или как обычный процесс. Монтирует `/proc`, `/sys`, `/dev`, `/tmp`, привязывает консоль |
| Ввод | `input.c` | Читает `/dev/input/event*`: громкость вверх/вниз, питание, назад. Без устройств ввода — режим stdin (`w/s/e/q`) для отладки |
| Интерфейс | `ui.h`, `ui_console.c`, `ui_fb.c` | Абстракция вывода, консольный и графический (framebuffer) бэкенды |
| Маскот | `mascot.c` | Оригинальный лисёнок Рику, пиксель-арт в коде |
| Тема | `theme.h` | Название, устройство, палитра |
| Шрифт | `font_data.h` | Генерируется `tools/genfont.py` (DejaVu Sans Mono, кириллица) |
| Меню | `menu.c` | Универсальное меню, подтверждение, окна сообщений |
| Разделы | `fstab.c` | Разбор `recovery.fstab`, монтирование, размонтирование, форматирование |
| Действия | `actions.c` | Перезагрузка, загрузчик, выключение, shell, лог, монтирование, очистка |
| Язык | `strings.c` | Русский по умолчанию, английский через `--lang=en` |
| Система | `sys.c` | `reboot()`, режим `RECOVERY_DRYRUN=1` |

## Сборка

```sh
make                      # хост, для отладки
make STATIC=1             # статический бинарник
make CC=armv7a-linux-androideabi21-clang STATIC=1   # NDK, 32-bit ARM
make CC=aarch64-linux-android21-clang STATIC=1      # NDK, 64-bit ARM
```

## Проверка на компьютере (безопасно)

```sh
cp recovery.fstab.example /tmp/test.fstab
RECOVERY_STDIN=1 RECOVERY_DRYRUN=1 RECOVERY_FSTAB=/tmp/test.fstab ./build/recovery
```

Клавиши: `w` — вверх, `s` — вниз, `e` — выбрать, `q` — назад (после каждой
клавиши Enter не нужен, если подавать ввод из файла/pipe).
`RECOVERY_DRYRUN=1` отключает настоящие mount, форматирование и reboot.

## Переменные окружения

- `RECOVERY_STDIN=1` — принудительно читать ввод из stdin
- `RECOVERY_DRYRUN=1` — ничего не менять в системе
- `RECOVERY_FSTAB` — путь к fstab (по умолчанию `/etc/recovery.fstab`)
- `RECOVERY_LOG` — путь к логу

## Следующие шаги

1. **Экран на реальных часах.** `ui_fb.c` написан по ioctl `FBIOGET_*`
   (16/24/32 bpp), но проверен только на виртуальном экране. Нужен тест
   на устройстве, возможно подстройка под панорамирование/`yoffset`.
2. **Образ.** Собрать ramdisk (`recovery` как `/init`, BusyBox, `mke2fs`,
   `recovery.fstab` в `/etc`), упаковать с родным ядром стокового
   `recovery.img` (Android Image Kitchen / `mkbootimg`).
3. **Установка ZIP.** Заглушка в `actions.c: act_install_zip`.
4. **Сенсор / одна кнопка.** Сейчас `BTN_TOUCH` считается «выбрать»;
   часам с одной кнопкой нужен короткое/длинное нажатие.
5. **ADB.** Для sideload нужен `adbd` в образе.

## Важно перед прошивкой на реальные часы

- Сначала снимите полный дамп прошивки и сохраните стоковый `recovery`.
- На Unisoc проверьте, что загрузчик можно разблокировать, иначе
  кастомный образ не загрузится.
- Не прошивайте раздел, который не умеете восстановить.

## Интерфейс

Стиль — смесь TWRP и OrangeFox: тёмный фон и нижняя навигационная панель
(TWRP), верхняя панель с маскотом, оранжевый акцент, скруглённые кнопки и
индикатор батареи (OrangeFox). Размеры подстраиваются под разрешение
экрана (на 480+ пикселей интерфейс масштабируется ×2).

Просмотр без устройства (кадры сохраняются в PPM):

```sh
mkdir -p /tmp/frames
RECOVERY_FB_VIRT=240x240 RECOVERY_FB_DUMP=/tmp/frames RECOVERY_STDIN=1 \
RECOVERY_DRYRUN=1 RECOVERY_BATTERY=87 ./build/recovery < keys.txt
```

Дополнительные переменные: `RECOVERY_UI=console` — принудительно текстовый
режим, `RECOVERY_FB_VIRT`/`RECOVERY_FB_DUMP` — виртуальный экран,
`RECOVERY_BATTERY` — подставить заряд.

## Свой маскот

Маскот в `src/mascot.c` — оригинальный, левая половина рисуется символами
и зеркалится. Чтобы поменять, правьте `left_half` и `color_of`. Если у вас
есть свой арт (например, ваш собственный персонаж), его можно будет
встроить как массив пикселей; не берите чужие арты и известных персонажей
без разрешения автора.

## Тач-управление

Если найден тачскрин (`/dev/input/event*` с `ABS_MT_POSITION_*` или
`ABS_X/ABS_Y` + `BTN_TOUCH`), включается режим под палец: кнопки выше,
подсказка «Нажмите на пункт».

- **Касание пункта** — выбрать и выполнить.
- **Свайп вверх/вниз** — прокрутка списка (на каждые ~1/6 высоты экрана
  один шаг, максимум 5 за жест).
- **Свайп вправо** — назад. Свайп влево ничего не делает.
- **Нижняя панель**: левая треть — назад, правая треть — домой.
- В **главном меню** «назад» игнорируется, чтобы случайный жест не
  перезагрузил часы.

Если на вашей панели касания «перевёрнуты», задайте переменные окружения
(например, в init-скрипте образа): `RECOVERY_TOUCH_SWAP=1` (поменять оси),
`RECOVERY_TOUCH_INVX=1`, `RECOVERY_TOUCH_INVY=1` (зеркалить). Подбирать
удобно по логу: каждое касание считается в координатах экрана.

Проверка без железа:

```sh
make test      # разбор касаний и свайпов через подставной канал
# ручной прогон: T x,y; — касание в точке экрана
printf 'T120,160;T120,52;T20,230;' | RECOVERY_STDIN=1 RECOVERY_DRYRUN=1 \
  RECOVERY_FB_VIRT=240x240 RECOVERY_FB_DUMP=/tmp/frames ./build/recovery
```

На реальном железе тач-ввод не проверялся: нет доступа к устройству.
